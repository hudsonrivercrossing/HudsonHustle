诊断

五个判断

一、最常做的事最费劲

抽牌是全局发生次数最多的动作，却每张牌弹一个全屏 “You drew Crimson” 要求点 Continue，然后再过两道交接弹窗。一局大约 60–80 个回合，光确认就多点几百次。

二、同一个对局屏写了两遍，而且已经走样

联机对局在 App.tsx:948-1227，本地对局在 LocalPlayScreen.tsx:426-673，九类逻辑重复。走样已经发生：本地模式没有禁用“第二张不能拿明牌机车”，联机模式不显示隧道翻牌。

三、联机可以作弊

服务端不校验任何客户端输入。审计中实际复现：发送 source:"bogus" 的抽牌动作可以连拿两张明牌机车。还可以免费偷看三张票再放回。

四、规则写了，但没有东西在执行

“只用 token” 对 1,320 条声明不成立；“release 冻结” 之后 release 仍被直接修改；README 说 v2.0 尚未完成而 v2.5 已发布；CLAUDE.md 引用的 screens/gameplay/ 目录不存在。CI 只跑测试和构建，没有 lint。

五、棋盘不是主角

本地双人局里，屏幕上有两个 “Open seat” 空位、一个无人可聊的 Chat 面板、九个颜色槽（多数为 0），棋盘只占 44%，而且没有任何地方告诉当前玩家 “这回合你可以做哪三件事”。

没有问题的部分

reduceGame 是纯函数、确定性、可种子复现；配置快照体系（draft / release / registry）设计合理；视觉语言（站牌搪瓷、票根、黄铜）有辨识度，不需要推翻。整改是换骨架，不是换皮。

Emil 的意见

按你的约定，先用 emil-ask-emil 路由，选了两项技能顺序执行：emil-design-foundations（结构是否对）和 emil-ui-review（按伤害程度排序的审查）。以下是按这两项技能的标准得出的结论。

结论：Blocked。有四项触及交互正确性和无障碍底线，必须先修。

Blocking

BeforeAfterWhy
线路与城市是 SVG 元素上的 onClick（BoardMap.tsx:485, 518），外层 role="img"（:218）；整张图没有任何 tabindex 或 role每条线路是可聚焦的 role="button"，aria-label="Secaucus 到 Penn District，3 格，Cobalt，隧道"，Enter 与空格触发；外层改 role="group"游戏的核心动作只有鼠标能做。role="img" 还会把里面的交互对读屏整体隐藏
顶栏三个图标按钮实测 22×22px；车票翻页按钮 24×26px可见尺寸可以不变，用伪元素把点击区扩到 44×4444px 是底线。22px 在触控板上都容易点偏
输入框计算字号 12px（玩家名、聊天框）输入框不低于 16pxiOS 在聚焦小于 16px 的输入框时会放大整页，联机邀请链接正是在手机上被打开
每次抽牌弹出全屏模态并带入场动画不弹窗；牌原位翻开后移入手牌，只动 transform 与 opacity，180ms一局发生上百次的动作不该有阻断和动画仪式。频率越高，反馈越要轻

Should fix

BeforeAfterWhy
屏幕上同时出现 8 种字重：400、650、700、740、780、820、840、900。加载的 IBM Plex Sans 是静态字重，请求到 800，而该字体最重只有 700三档：400 / 500 / 600。Fraunces 是可变字体，可单独用 600–700不存在的字重由浏览器合成，笔画发糊。八档字重也说明层级靠 “加粗” 在撑，而不是靠大小和留白
页面上出现 12.16px、14.4px、16.32px 这类字号；token 里有 13 级字号，其中 6px 和 8pxUI 字号收敛到 6–7 级，最小 12px；地图标注单独一套并随缩放带小数的字号来自 em 相乘，说明字号不是从 token 取的。10px 的正文级文字在笔记本上读不清
34 处 :hover，没有一处包在 @media (hover: hover) 里；:active 只有 5 处hover 样式进 hover 媒体查询；所有按钮、牌、车票加按压态（scale(0.97)，约 100ms）触屏上 hover 会粘住。没有按压态的按钮感觉是死的，卡牌游戏尤其需要 “按下去” 的手感
过渡曲线统一用内置 ease；9 个 keyframes 只有 2 处 prefers-reduced-motion入场用 cubic-bezier(0.22, 1, 0.36, 1) 一类的强 ease-out，退场更快；全局一条 reduced-motion 规则兜底内置曲线太弱，动效显得含糊。时长（140–220ms）本身是对的，不用改
100vh 出现 10 次，没有 dvh，没有 safe-area-inset单屏应用用 100dvh，底部托盘加 env(safe-area-inset-bottom)移动浏览器的地址栏会让 100vh 溢出一截，底部按钮被切掉
圆角 token 有 12 个不同的值（1 / 2 / 3 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 18 / 24px），对局屏上实际出现 8 种四档：4（芯片）/ 8（控件、牌）/ 12（面板）/ 16（弹窗）。嵌套时内圆角 = 外圆角 − 内边距面板套卡片套芯片时各用各的圆角，转角处间隙不均。这是 “看着有点不对但说不出来” 的主要来源
手牌区显示全部 9 个颜色槽，数量为 0 的也占位；牌市每张牌上有一个永远是 “1” 的数字手牌只显示持有的颜色，按数量排序；牌市去掉数字层级靠减法。五个 “0” 和五个 “1” 是噪音，把真正要看的三个数字淹没了
颜色 token 是 hex 与 rgba 混用，表面色靠半透明叠加（rgba(250,244,233,0.9)），另有 1,028 处 rgba 字面量散落在组件 CSS 里token 迁到 OKLCH；表面色用不透明实色，按层级定三档明度；hover 用 color-mix(in oklch, …) 派生半透明表面叠在照片背景上，实际颜色不可控，对比度无法保证。暗色模式下 alpha 边框会发光，应改实色
设置页是居中的小卡片，两侧各挂一张说明卡；1440 宽下主体只占约 300px 宽一屏式设置，主体放宽到约 720px，摘要并入主体三张卡同等视觉重量，不知道该看哪张。每屏应只有一个主要动作

Nits

  • index.html 没有 description、OG 图、favicon、theme-color。分享房间链接时预览是空白的。
  • 文案：“0 bot · 1 human open” 读不懂；“Hudson Hustle Anchor Prototype” 是内部命名；计时器帮助文字与控件不符。按钮用具体结果命名是对的（“Keep 2 tickets” 很好），保持。
  • 数字只有 7 处用了 tabular-nums。牌堆数、车厢数、分数这些会跳动的数字都应该用。
